# Full-Stack Web Engineering — 162-Day Roadmap

This is a depth-first professional progression, not a compressed survey. The numbered spine runs from first semantic HTML through production cloud operations. Atomic topics remain in the phase source files; these syllabus documents describe capability, project ladder, transfer work, and evidence.

## Entry contract and evidence

The learner needs a computer, terminal, editor, browser, GitHub account, and willingness to type and inspect code. Prior programming is not assumed. Setup gaps are repaired inside the first relevant day rather than treated as hidden prerequisites.

- **Covered:** encountered the mechanism and its motivating failure.
- **Built with help:** the artifact works and assistance is recorded.
- **Independent:** the critical path is reconstructed without the answer open.
- **Recalled:** the mechanism is produced after a meaningful delay.
- **Transferred:** a changed domain is solved without being told which technique to use.

Finishing a day records exposure; it does not automatically claim all five levels. Phase gates ask for explanation, diagnosis, reconstruction, and a changed requirement as well as a working artifact.

## Why this order is dependency-safe

```text
semantic page -> browser behavior -> typed network boundary -> component state
-> HTTP service -> durable data -> identity policy -> server-rendered product
-> money/files/live events -> verification -> queues -> delivery -> cloud operation
```

Each new layer first exposes a failure in the previous layer. TypeScript follows real async JavaScript; React follows DOM and state work; databases follow an in-memory API; authentication follows database ownership; Next.js follows React and server boundaries; production systems follow a complete full-stack product.

## Project and gate rules

Every project specifies a user and decision, constraints and failure states, evidence of correctness, a changed requirement for transfer, and an explicit boundary. Projects are not branded clones, close analogues, or cosmetic renames. The domain, data, interaction, stakeholder, and success criteria change together.

Every phase begins with a useful, deployable or runnable win. Later gates revisit earlier skills under changed conditions: local state becomes server state, a single-user rule becomes tenant isolation, a successful request becomes an idempotent job, and a deployed service becomes an operated service with budgets, alerts, and rollback.

A credible completion packet contains live artifacts, source history, tests tied to named risks, architecture and threat-model notes, query and performance evidence, accessibility checks, runbooks, cost notes, and transfer attempts. It does not claim job guarantees or mastery merely from watched content.
