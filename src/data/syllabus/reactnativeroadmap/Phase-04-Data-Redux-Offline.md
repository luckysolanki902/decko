# Phase 4 — Data, Redux & Offline-First State

**Days 17–22 · Outcome:** build honest data UX for slow, failed, stale, retried, and offline operations.

- Day 17: `fetch`, request state machines, effects, cleanup, aborts, stale responses, retry, and connectivity changes.
- Day 18: Redux Toolkit from scratch—store, slices, reducers, actions, dispatch, typed hooks, selectors, normalization, and state placement.
- Day 19: thunks, cancellation, RTK Query cache keys, invalidation, polling, optimistic changes, rollback, and normalized errors.
- Day 20: typed forms, schema validation, field/form/server errors, radios, selects, switches, dates, drafts, and duplicate-submit prevention.
- Day 21: ordinary versus secure storage, persistence boundaries, migrations, offline queues, idempotency, retries, and conflicts.
- Day 22: build the Cooperative Pantry Ledger for volunteers reserving limited stock across household requests. Normalize items, requests, and reservations; persist drafts and a mutation queue; make duplicate retries idempotent; distinguish local, queued, synced, and conflicted states; and prove restart, stale-response, duplicate-submit, migration, and conflict behavior. Transfer the model to partial fulfilment. Payments, identity checks, delivery routing, and a production backend stay out of scope.
