# Phase 9 — Production Delivery & Operations

**Days 48–52 · Outcome:** create signed releases, roll them out safely, observe failures, and recover.

- Day 48: native binaries versus JS bundles, EAS profiles, Android signing, Apple certificates/profiles, secrets, environments, and reproducibility.
- Day 49: EAS Update compatibility, runtime versions, branches, channels, startup behavior, rollout, rollback, and binary-required changes.
- Day 50: identifiers, versions, build numbers, EAS Submit, TestFlight, Play tracks, privacy disclosures, screenshots, review, and phased rollout.
- Day 51: crash reports, symbols, source maps, breadcrumbs, startup/network/ANR traces, privacy-safe analytics, SLOs, alerts, and triage.
- Day 52: run the Indie Cinema Release Train for a supplied programme app. Produce reproducible development, preview, and production profiles; separate credentials, secrets, versions, and environments; roll a schedule-text update forward and back; hold a native notification change for a new binary; symbolicate an intentional crash; and prepare privacy-safe signals, store metadata, accessibility notes, and an incident runbook. Transfer the response to a bad update affecting only one runtime version. Real publication, payments, accounts, and live credentials stay out of scope.
