# Phase 8 — PostgreSQL, Transactions & Authentication

**Days 36–40 · Outcome:** persist state safely and enforce identity and authorization on the server.

- Day 36: PostgreSQL, `database/sql`, connection pools, drivers, context-aware queries, scanning, row cleanup, parameters, and prepared statements.
- Day 37: keys, constraints, indexes, timestamps, migrations, repository boundaries, SQL visibility, and sqlc awareness.
- Day 38: transaction lifecycle, isolation, allocation anomalies, locks, atomic updates, unique constraints, idempotency keys, and retryable failures.
- Day 39: password hashing, opaque sessions versus JWTs, secure cookies, CSRF, rotation, RBAC, and resource-level authorization.
- Day 40: build a Laboratory Sample Custody API with an append-only custody history, atomic technician handoffs, secure sessions, technician/supervisor policies, reversible migrations, and PostgreSQL integration tests proving one sample cannot gain two current custodians.
