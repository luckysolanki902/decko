# Phase 6 — Testing, Debugging, Performance & Security

**Days 26–30 · Outcome:** prove correctness and improve performance through evidence from Go's toolchain.

- Day 26: `testing.T`, subtests, helpers, table tests, boundary selection, fakes, interface seams, `httptest`, and isolated filesystems.
- Day 27: fuzz seed corpora, properties, deterministic targets, minimization, reproduction, regression promotion, and target selection.
- Day 28: honest benchmarks, allocation measurement, CPU and heap profiles, pprof interpretation, optimization, and re-measurement.
- Day 29: minimal reproductions, debugging workflow, race-detector coverage, `govulncheck`, input limits, timeouts, secrets, and secure defaults.
- Day 30: build an Untrusted Telemetry Decoder Lab that handles truncation, corrupt lengths, duplicate fields, oversized payloads, and pathological nesting without panics, backed by table tests, minimized fuzz regressions, benchmark and profile evidence, resource ceilings, race checks, and `govulncheck`.
