# Go Engineering Roadmap — Overview

## Outcome

This 55-day course teaches Go from the first compiled program to a production-shaped disaster-relief supply network. It is standard-library-first: language mechanics, packages, concurrency, testing, and `net/http` are understood before larger infrastructure is introduced.

## Sequence

| Phase | Days | Focus | Phase project |
|---|---:|---|---|
| 1 | 1–5 | Toolchain, values, flow, functions | Trail Ration Planner CLI |
| 2 | 6–10 | Collections, strings, memory | Field Sensor Stream Summarizer |
| 3 | 11–15 | Structs, methods, interfaces, errors | Multi-Source Habitat Importer |
| 4 | 16–20 | Modules, packages, I/O, JSON, CLI design | Research Archive Catalog CLI |
| 5 | 21–25 | Goroutines, channels, context, synchronization | Parallel Archive Verifier |
| 6 | 26–30 | Tests, fuzzing, benchmarks, pprof, security | Untrusted Telemetry Decoder Lab |
| 7 | 31–35 | Production-shaped APIs with `net/http` | Community Tool Library API |
| 8 | 36–40 | PostgreSQL, transactions, sessions, authorization | Laboratory Sample Custody API |
| 9 | 41–45 | Redis, jobs, gRPC, observability, reliability | Watershed Telemetry Pipeline |
| 10 | 46–50 | Docker, Compose, CI, deployment | Deployed Watershed Operations Stack |
| 11 | 51–55 | Integrated system design and delivery | Disaster Relief Supply Network |

## Daily learning contract

Each lecture begins with a mental model, teaches mechanics through progressively larger examples, names failure modes, and ends with a five-rep hands-on practice ladder, common-mistakes table, cheat sheet, and ten-question final quiz. Every phase ends with one independently explainable project rather than a tutorial clone.

## Final portfolio proof

The final capstone must demonstrate that concurrent allocations cannot drive depot stock below zero, not merely expose CRUD endpoints. The submission includes a deployed API, PostgreSQL migrations and inventory ledger, Redis-backed projections, background workers, idempotent carrier-update reconciliation, authorization and abuse tests, load evidence, observability, Docker images, Compose setup, CI, backup restoration, architecture decisions, a runbook, and a concise demo.
